# 从营销判断到小红书文案的翻译层

## 这个文件解决什么问题

**现状**：策略摘要填完了，但标题还是很平淡，像产品说明书。

**根本原因**：营销判断和文案创作之间缺少**翻译机制**。知道"核心价值是什么"，但不知道"如何把它变成标题中的那句话"。

**本文件提供**：
1. 从策略摘要每个字段到实际文案的转化规则
2. 8 种经过验证的小红书标题模式
3. 标题生成与筛选的完整流程
4. 强制检查清单

---

## 第一部分：六大翻译规则

这些规则确保策略摘要中的每个判断都能真正改变最终文案。

### 翻译规则 1：核心价值必须进入 PAGE 01 主标题

**原则**：策略摘要中的"核心价值"不能只停留在表格里，必须在封面主标题中体现。

**转化步骤**：

1. **提取核心价值中的用户任务或结果**
   - 不要："根据真实工作选择配置位置"（功能描述）
   - 要："让 AI 永久记住你的工作习惯"（用户想要的结果）

2. **识别最强的情绪触发点**
   - 痛点：正在浪费什么、错失什么
   - 向往：理想状态是什么样的

3. **选择包装方式**
   - 痛点 + 方案暗示："每次都要重教 AI？一次配置永久生效"
   - 结果承诺："AI 像合作 3 年的同事，只说关键词就懂"
   - 对比反差："从每次重教，到永久记住"

**转化表**：

| 核心价值（策略摘要） | 用户任务/结果 | 封面主标题 |
|-------------------|-------------|-----------|
| 根据真实工作选择配置位置；修改前先预览 | 让 AI 记住工作习惯，不担心改错 | "AI 总是记不住你？一次配置，持久保存" |
| 5 分钟配置，写入本地文件 | 省下每天重复解释的时间 | "5 分钟配置，AI 永久记住你" |
| 把配置带到新设备 | 换设备也能继续用熟悉的 AI | "换电脑也能带走的 AI 工作记忆" |

**注意事项**：
- "永久记住""持久保存"需要有技术证据支撑（写入本地文件、数据库等）
- 避免无证据的效果承诺（如"效率提升 300%""彻底解决问题"）
- 如果材料只说"配置"，可以说"让 AI 记住"，但不要说"永久生效"（生效是效果）

**检查标准**：
- [ ] 封面主标题直接提到或暗示了核心价值
- [ ] 用户能从标题看到"我能获得什么"
- [ ] 不是功能描述，而是结果描述
- [ ] 结果承诺有材料证据支撑

---

### 翻译规则 2：当前替代必须形成对比张力

**原则**：策略摘要中的"当前替代方案"要转化为标题或正文中的"对比"，让用户看到新旧差异。

**转化步骤**：

1. **识别旧做法的核心缺陷**
   - 每次重新说明 → 浪费时间、打断思路
   - 重复复制 Prompt → 容易出错、难以管理
   - 手动整理配置 → 找不到冲突在哪

2. **提炼新方案如何避免这个缺陷**
   - 一次配置 vs 每次重复
   - 智能检查 vs 手动排查
   - 自动记住 vs 手动粘贴

3. **形成对比表达**
   - 动作对比："从复制粘贴到一键调用"
   - 状态对比："别人还在重教，你已经一劳永逸"
   - 时间对比："过去 30 分钟，现在 5 分钟"

**转化表**：

| 当前替代方案（策略摘要） | 核心缺陷 | 对比标题/正文 |
|-----------------------|---------|-------------|
| 每次重新说明背景和输出要求 | 浪费时间、打断思路 | "别再当 AI 的复读机" |
| 重复复制同一套 Prompt | 容易出错、难以管理 | "从手动粘贴到自动调用" |
| 手动整理配置冲突 | 找不到哪里冲突了 | "配置冲突？3 秒帮你找出来" |

**应用位置**：
- PAGE 01：可用于封面或核心说明
- PAGE 02-03：用于方法页或对比页
- 重点词标记：旧做法用 SECONDARY，新方案用 ACCENT

**检查标准**：
- [ ] 至少有一页形成了新旧对比
- [ ] 对比是具体的（动作、时间、结果），不是抽象的"更好"
- [ ] 旧做法是 TA 真实经历，不是虚构的

---

### 翻译规则 3：TA 触发场景必须用于封面识别

**原则**：策略摘要中的"TA 触发场景"要让目标读者立刻认出"这说的就是我"。

**关键约束**：只有材料明确提供触发场景时才应用此规则。如果策略摘要中该字段为"当前材料未提供；待确认"，则用痛点问句或核心价值作为封面，**不得虚构场景**。

**转化步骤**（仅当材料提供触发场景时）：

1. **把场景描述变成读者能感同身受的瞬间**
   - 不要："使用 ChatGPT 时需要配置"（抽象）
   - 要："每次开新对话，又要把背景讲一遍"（具体瞬间）

2. **选择呈现方式**
   - 问句式：直接提问，让读者回答"是"
   - 陈述式：描述正在发生的事
   - 对话式：用读者可能说的话

3. **增加识别细节**
   - 时间细节："每次""又要""第 3 次"
   - 情绪细节："烦""急""乱"
   - 具体对象："背景""风格""要求"

**转化表**：

| TA 触发场景（策略摘要） | 具体瞬间 | 封面标题 |
|-----------------------|---------|---------|
| 每次开新对话都要重新解释背景 | 刚解释完，下个对话又要重来 | "刚解释完，下个对话又要重来一遍？" |
| 准备迁移到新设备 | 换新电脑，所有配置都得重来 | "换新电脑，AI 配置全得重来？" |
| 配置开始重复、冲突或错位 | Custom Instructions 越写越乱 | "Custom Instructions 越写越乱？" |

**检查标准**：
- [ ] 封面标题或核心说明中包含了触发场景
- [ ] 战略 TA 能立刻认出"这就是我遇到的情况"
- [ ] 用了具体细节，不是泛泛的"想提高效率"

---

### 翻译规则 4：主要疑虑必须匹配证据页

**原则**：策略摘要中的"主要疑虑"决定需要哪些证据页，以及证据页的标题和内容重点。

**转化步骤**：

1. **识别疑虑类型**
   - 有效性疑虑："真的有用吗？"
   - 复杂度疑虑："会不会很难？"
   - 风险疑虑："会不会搞乱现有的？"
   - 时机疑虑："为什么要现在做？"

2. **匹配证据类型**
   - 有效性 → 案例、数据、用户反馈
   - 复杂度 → 演示、步骤、时间承诺
   - 风险 → 权限说明、边界、预览机制
   - 时机 → 当前代价量化、机会窗口

3. **设计证据页标题**
   - 不要："权限与迁移"（功能名称）
   - 要："先预览，确认后才改动"（消除疑虑）

**转化表**：

| 主要疑虑（策略摘要） | 疑虑类型 | 证据类型 | 证据页标题示例 |
|-------------------|---------|---------|---------------|
| 会不会很复杂 | 复杂度 | 演示/步骤 | "3 步完成，不用学新知识" |
| 会不会搞乱现有配置 | 风险 | 权限/预览 | "先预览，确认后才改动" |
| 换设备能带走吗 | 可行性 | 迁移说明 | "一个命令，配置跟你走" |
| 真的有效吗 | 有效性 | 案例/数据 | "16 项测试，3 个月实测" |

**关键规则**：
- 每个主要疑虑至少对应一页
- 证据页标题要直接回应疑虑，不要只是介绍功能
- 证据必须真实，不能虚构

**检查标准**：
- [ ] 策略摘要中的每个主要疑虑都有对应的证据页
- [ ] 证据页标题直接回应疑虑，而非描述功能
- [ ] 证据是独立的（不只是产品自述）

---

### 翻译规则 5：阅读路径决定页序和页面任务

**原则**：策略摘要中的"阅读路径"不是功能目录，而是读者状态变化的顺序。每个状态变化对应一页。

**转化步骤**：

1. **把阅读路径拆解成独立状态**
   - "认出问题 → 相信方案 → 消除疑虑 → 行动"
   - = 4 个状态 = 最多 4 页

2. **为每个状态写页面任务**
   - 不要："介绍配置位置"（功能介绍）
   - 要："让读者从不知道如何分类配置 → 知道三种配置位置"（状态变化）

3. **检查是否必需**
   - 删掉这一页，读者还能走到下一个状态吗？
   - 能 → 合并或删除
   - 不能 → 保留

**转化表**：

| 阅读路径（策略摘要） | 拆解为独立状态 | 页序 | 每页任务 |
|-------------------|--------------|-----|---------|
| 认出问题 → 相信方案 → 消除疑虑 → 行动 | 4 个状态 | 4 页 | P1: 认出问题<br>P2: 核心方案<br>P3: 消除疑虑<br>P4: CTA |
| 认出问题 → 看方法 → 看效果 → 行动 | 4 个状态 | 4 页 | P1: 问题<br>P2: 方法<br>P3: 效果<br>P4: CTA |
| 问题 → 答案 → 行动 | 3 个状态 | 3 页 | P1: 问题<br>P2: 答案<br>P3: CTA |

**错误示范**：
```
阅读路径：理解配置位置 → 看到两种入口 → 了解权限边界
页序：配置位置 → 使用入口 → 权限说明
```
**问题**：这是产品功能教育，不是决策推动。

**正确示范**：
```
阅读路径：认出"反复重教" → 相信"能记住" → 消除"会不会复杂" → 立刻尝试
页序：封面痛点 → 核心方案 → 简单演示 → 行动 CTA
```

**检查标准**：
- [ ] 页序来自读者决策变化，不是功能目录
- [ ] 每页都推动一次状态变化
- [ ] 删除任何一页后，决策路径会断裂

### 翻译规则 6：读者唯一行动必须变成末页 CTA

**原则**：策略摘要中的"读者唯一行动"必须直接转化为末页 CTA，且要具体、低门槛、与传播目标一致。

**转化步骤**：

1. **检查传播目标**
   - 目标：促成安装 → CTA 必须是安装入口
   - 目标：收藏方法 → CTA 必须是收藏提示
   - 目标：接受判断 → CTA 必须是应用判断

2. **降低行动门槛**
   - 不要："了解更多"（模糊）
   - 不要："访问官网安装"（需要多步）
   - 要："GitHub 搜索 [名称]"（一步可完成）

3. **给出具体指令**
   - 包含关键词或操作对象
   - 5 分钟内能开始
   - 不需要额外决策

**转化表**：

| 传播目标 | 读者唯一行动（策略摘要） | 错误 CTA | 正确 CTA |
|---------|----------------------|---------|---------|
| 促成安装 | 打开 GitHub，按 README 安装 | "了解更多" | "GitHub 搜索 supbewhy-p13n" |
| 收藏方法 | 保存清单备用 | "点赞收藏" | "收藏这份清单，遇到直接用" |
| 尝试配置 | 发送配置指令 | "开始使用" | "把这句话发给 Codex：[完整指令]" |
| 接受判断 | 改变一个评估标准 | "记住这个" | "下次评估时，先看 [具体标准]" |

**常见 CTA 类型**：

| 内容类型 | 合适 CTA | 避免 |
|---------|---------|------|
| 产品/工具 | 安装、试用、下载入口 | "了解更多""点击链接" |
| 教程 | 立即做第一步、收藏备用 | "学会了吗" |
| 方法 | 应用到具体场景、保存到工作流 | "点赞收藏" |
| 观点 | 改变一个判断、讨论、转发 | "记住这个观点" |
| 案例 | 对照自己情况、采用机制 | "向TA学习" |
| 资源 | 收藏、逐项检查、领取 | "关注不迷路" |

**检查标准**：
- [ ] CTA 与传播目标一致
- [ ] CTA 具体，包含关键词或对象
- [ ] CTA 可在 5 分钟内开始执行
- [ ] 没有用"了解更多""点赞收藏"等空泛表达

## 第二部分：小红书标题模式库

基于《种草》和小红书平台特征，提供 8 种经过验证的标题模式。每个模式都经过实际测试，适用于不同的内容类型和页面角色。

### 模式使用原则

1. **不要机械套用**：模式是参考，不是模板
2. **必须有真实支撑**：标题中的每个要素（数字、对比、效果）都必须在正文中有证据
3. **避免连续重复**：全组标题不要连续使用同一模式
4. **根据页面角色选择**：不同页面适合不同模式

---

### 模式 1：痛点场景 + 解决方案

**结构**：`[具体痛点场景] + [解决方案暗示或结果]`

**适用**：
- 封面（PAGE 01）
- 产品、工具、方法类内容

**核心要素**：
- 痛点要具体到让 TA 立刻认出（时间、频率、情境）
- 解决方案要给出"结果"而非"功能"
- 时间或难度承诺要可验证

**示例**：
- ✓ "每次开新对话都要重教 AI？一次配置永久生效"
- ✓ "Custom Instructions 越写越乱？3 步整理清楚"
- ✓ "换电脑 AI 配置全得重来？这个方法一键迁移"

**错误用法**：
- ❌ "AI 不好用？试试这个"（痛点不具体）
- ❌ "配置管理工具介绍"（没有痛点）
- ❌ "解决 AI 配置问题"（方案太模糊）

**生成步骤**：
1. 从策略摘要中找到"TA 触发场景"
2. 把场景转化为问句或陈述
3. 从"核心价值"中提取结果
4. 用"？"或"，"连接

---

### 模式 2：结果量化 + 方法暗示

**结构**：`[可量化的结果] + [简单方法提示]`

**适用**：
- 封面或核心答案页
- 有明确数据支撑的产品或方法

**核心要素**：
- 数字必须真实可验证（时间、次数、测试数）
- 结果要与 TA 在意的指标挂钩
- 避免"提升 300%"等夸张表达

**示例**：
- ✓ "5 分钟配置，每天省 10 分钟重复解释"
- ✓ "3 个月实测，AI 终于记住我的风格"
- ✓ "16 项测试覆盖，配置不再出错"

**错误用法**：
- ❌ "效率提升 500%"（夸张，无证据）
- ❌ "用的人都说好"（无数据）
- ❌ "快速配置"（没有量化）

**生成步骤**：
1. 从材料中找到可验证的数字（时间、测试数、使用时长）
2. 把数字与用户关心的指标关联
3. 补充方法的简单程度

---

### 模式 3：对比反差

**结构**：`[旧状态] → [新状态]` 或 `[别人] vs [你]`

**适用**：
- 核心答案页或方法页
- 有明确替代方案的产品或方法

**核心要素**：
- 对比要具体（动作、时间、结果），不只是"更好"
- 旧状态要是 TA 真实经历
- 新状态要可达成，不夸张

**示例**：
- ✓ "从每次重教，到永久记住"
- ✓ "别人还在复制粘贴 Prompt，你已经一键调用"
- ✓ "过去 30 分钟，现在 5 分钟"

**错误用法**：
- ❌ "比其他工具更好"（抽象，无对比维度）
- ❌ "新一代配置方案"（空泛）
- ❌ "从慢到快"（对比不具体）

**生成步骤**：
1. 从策略摘要中找到"当前替代方案"
2. 提炼旧做法的核心缺陷（时间、错误率、复杂度）
3. 提炼新方案如何避免
4. 形成明确对比

---

### 模式 4：反常识 / 颠覆认知

**结构**：`[常见错误做法] + [正确做法]`

**适用**：
- 核心答案页
- 观点、方法类内容

**核心要素**：
- 必须有真实洞察支撑
- 不为了反常识而反常识
- 正文必须给出"为什么"

**示例**：
- ✓ "Custom Instructions 不是写得越多越好"
- ✓ "AI 记不住你？不是模型问题，是配置方法错了"
- ✓ "配置 AI 个性化，最该放的不是 Prompt"

**错误用法**：
- ❌ "你的 AI 用法全错了"（过于绝对，无具体指向）
- ❌ "99% 的人不知道"（标题党）
- ❌ "这才是正确方法"（没有说明错在哪）

**生成步骤**：
1. 识别常见误区（从材料或 TA 替代方案中找）
2. 明确错误的核心
3. 用否定句指出
4. 可选：补充正确方向

---

### 模式 5：具体损失警示

**结构**：`[正在发生的具体损失] + [可避免的提示]`

**适用**：
- 封面或问题意识页
- 有明确代价的问题

**核心要素**：
- 损失要可量化或可感知
- 不能制造焦虑而无法解决
- 要给出避免路径

**示例**：
- ✓ "每天 30 分钟在重复解释，一年 182 小时"
- ✓ "你的 AI 配置，正在被其他项目拖累"
- ✓ "没备份配置，换设备等于从零开始"

**错误用法**：
- ❌ "不这样做会很惨"（制造焦虑，无具体损失）
- ❌ "浪费了很多时间"（不可量化）
- ❌ "你正在犯错"（无具体指向）

**生成步骤**：
1. 从策略摘要"核心任务"中找到维持现状的代价
2. 把代价量化（时间、次数、错误率）
3. 可选：暗示可避免

---

### 模式 6：理想状态描绘

**结构**：`[向往的具体状态]`

**适用**：

## 深度判断标准：如何识别"不够好"的标题

即使标题通过了五项测试，仍需要用这 7 个深度标准判断：

### 标准 1：功能 vs 结果测试

**问题**：这个标题在讲"产品能做什么"，还是"用户能获得什么"？

**判断方法**：
- 功能词汇：配置、设置、管理、选择、分层、映射、位置
- 结果词汇：记住、带走、省时间、不用重复、自动、永久

**示例**：
- ❌ "先把稳定要求放对位置"（功能）
- ✓ "一次配置，永久记住"（结果）

**改进公式**：
```
功能标题 → 问"用户用它完成什么" → 转化为结果
"放对位置" → 让 AI 记住 → "永久记住"
```

---

### 标准 2：抽象 vs 具体测试

**问题**：标题中的词汇是抽象概念还是具体画面？

**判断方法**：
- 抽象词：稳定要求、协作规则、个性化、优化、提升
- 具体词：重教、3 个问题、5 分钟、预览、确认

**示例**：
- ❌ "把稳定要求放对位置"（抽象）
- ✓ "问你 3 个问题就能配好"（具体）

**改进公式**：
```
抽象词 → 用数字/动作/场景替换 → 具体词
"稳定要求" → 长期习惯、项目规则、固定流程（列举）
"很简单" → 3 个问题，5 分钟（量化）
```

---

### 标准 3：书面语 vs 口语化测试

**问题**：标题读起来像官方公告，还是像朋友聊天？

**判断方法**：
- 书面语：重讲、进行配置、实现优化、提升效率
- 口语化：重教、配一下、搞定、省时间

**示例**：
- ❌ "每次开新对话都要重讲"（书面语）
- ✓ "每次都要重教 AI"（口语化）

**改进公式**：
```
书面语 → 想象你在跟朋友说 → 口语化
"重讲" → "重教"
"进行配置" → "配一下"
"实现" → "搞定"
```

---

### 标准 4：产品视角 vs 用户视角测试

**问题**：标题是站在产品角度说话，还是站在用户角度说话？

**判断方法**：
- 产品视角：P13N 会...、本工具提供...、功能包括...
- 用户视角：你的 AI、你的习惯、你的工作、你能...

**示例**：
- ⚠️ "P13N 会把不同要求分到各自入口"（产品视角，但可接受）
- ✓ "AI 会按你的真实工作，推荐配置位置"（用户视角）

**改进公式**：
```
产品主语 → 改为用户主语或用户对象 → 用户视角
"P13N 会分配" → "AI 会按你的工作推荐"
```

---

### 标准 5：情绪强度测试

**问题**：标题是否有情绪感染力？还是平铺直叙？

**判断方法**：
- 低情绪：说明、介绍、方法、原理
- 高情绪：每次都要、又要、才、终于、别再

**示例**：
- ❌ "配置位置的选择方法"（零情绪）
- ✓ "每次都要重教 AI？"（有情绪）

**改进公式**：
```
平铺直叙 → 加入时间词/情绪词 → 有感染力
"需要重新解释" → "每次都要重教"
"配置方法" → "别再每次重讲"
```

---

### 标准 6：信息密度测试

**问题**：标题是否信息量充足？还是只说了一半？

**判断方法**：
一个好标题应包含至少 2 个信息点：
- 痛点 + 方案
- 旧做法 + 新做法
- 问题 + 结果
- 时间 + 效果

**示例**：
- ❌ "每次开新对话都要重讲？"（只有痛点）
- ✓ "每次都要重教 AI？一次配置，永久记住"（痛点 + 方案 + 结果）

**改进公式**：
```
单一信息 → 补充对应信息 → 完整张力
只有痛点 → + 方案
只有方案 → + 痛点或结果
```

---

### 标准 7：删除测试（终极标准）

**问题**：如果删除产品名，标题是否仍有吸引力？

**判断方法**：
把标题中的产品名、品牌词删掉，看是否仍能吸引 TA。

**示例**：
- ❌ "使用 P13N 配置 AI"删掉"P13N"→"配置 AI"（无吸引力）
- ✓ "每次都要重教 AI？一次配置，永久记住"（没有产品名，仍有吸引力）

**改进公式**：
```
依赖产品名 → 用痛点/结果替代 → 独立吸引力
"使用 P13N 配置" → "每次都要重教？一次配置，永久记住"
```

## 第三部分：标题生成与筛选流程

这是 Skill 内部执行流程，不输出给用户。

### 步骤 1：回顾策略摘要

- 战略 TA
- TA 触发场景
- 当前替代方案
- 核心价值
- 主要疑虑
- 本页任务（从阅读路径中确定）

### 步骤 2：选择 1-2 个候选模式

根据本页角色选择合适的模式：

| 页面角色 | 优先模式 | 次选模式 |
|---------|---------|---------|
| 封面（PAGE 01） | 模式 1（痛点+方案）<br>模式 6（理想状态） | 模式 5（损失警示） |

| 权限/边界 | 直接陈述，不用模式 | - |
| 行动（末页） | 模式 6（理想状态）<br>低门槛承诺 | - |

### 步骤 3：生成 3 个候选（内部，不输出）

用不同模式或角度生成 3 个候选，确保：
- 不是同义词替换，而是不同张力来源
- 每个都能独立成立
- 都有材料支撑

**PAGE 01 示例**：
```
候选 1（模式 1）："每次都要重教 AI？一次配置永久生效"
候选 2（模式 6）："AI 像合作 3 年的同事，只说关键词就懂"
候选 3（模式 5）："每天 30 分钟在重复解释，这个方法省回来"
```

### 步骤 4：执行五项通过测试

逐个测试每个候选：

| 测试项 | 检查标准 | 示例（通过） | 示例（不通过） |
|-------|---------|------------|--------------|
| **读者识别** | 战略 TA 能认出场景、任务或决定 | "每次都要重教 AI？" | "AI 配置问题" |
| **具体性** | 至少有一个具体动作、对象、损失或结果 | "一次配置永久记住" | "更好的方案" |
| **独立成立** | 离开页码和正文也能读懂，无空指代 | "Custom Instructions 越写越乱？" | "这个方法很有用" |
| **信息张力** | 给出冲突、代价、意外或值得继续看的缺口 | "5 分钟配置，每天省 10 分钟" | "配置很简单" |
| **事实承载** | 正文和证据能支撑，不靠夸张 | "16 项测试覆盖" | "效率提升 500%" |

### 步骤 5：选择初步胜出标题

- 五项全通过 → 进入步骤 6 二次优化
- 多个通过 → 选**信息张力**最强且最符合本页任务的，进入步骤 6
- 全不通过 → 返回策略摘要，重新提炼场景或价值

### 步骤 6：二次优化（强制步骤）

**关键**：五项测试只是及格线（60-70分），要达到卓越水准（85-90分），必须执行二次优化。

#### 6.0 功能模式识别（第一道防线，一票否决）

**在进行 7 个深度标准检查之前，先执行功能模式识别。**

**如果标题包含以下任一模式，立刻判定为功能描述，必须重写**：

| 功能模式 | 为什么是功能 | 必须改为什么 | 改写示例 |
|---------|------------|------------|---------|
| "把...放..." "...放到..." "...放对..." | 在讲配置动作，不是用户结果 | "让 AI 记住" "永久记住" "不用重复" | ❌ "把习惯放对位置"<br>✓ "让 AI 永久记住你的习惯" |
| "...分开..." "...分层..." "...分配..." | 在讲系统设计，不是用户利益 | "AI 会按你的工作推荐" "问你 3 个问题" | ❌ "把习惯、项目、重复工作分开配置"<br>✓ "AI 会按你的真实工作，推荐配置位置" |
| "...位置..." "...入口..." "...映射..." | 在讲产品架构，不是用户任务 | "让 AI 记住" "5 分钟搞定" | ❌ "配置位置的选择"<br>✓ "问你 3 个问题就能配好" |
| "配置..." "设置..." "管理..." 开头 | 功能动词，不是结果 | "让 AI..." "AI 会..." "不用..." | ❌ "配置个性化 AI"<br>✓ "让 AI 记住你的习惯" |
| "...方法..." "...原理..." "...方式..." | 在讲抽象概念，不是具体价值 | 用具体动作或结果替代 | ❌ "配置的方法"<br>✓ "3 个问题，5 分钟搞定" |

**检查流程**：
1. 逐词扫描初步胜出标题
2. 发现任一功能模式词 → 立刻判定不通过
3. 参考"必须改为什么"列，重写标题
4. 重新生成后，再次检查是否包含功能模式
5. 直到不包含任何功能模式，才进入 6.1

**为什么这是第一道防线**：
- 功能模式是最常见的错误（占 80%）
- 一旦出现，标题就是 60 分水准
- 必须在进入深度检查前彻底消除

**错误标题 1**：


**识别功能模式**：
- 包含"分开"（系统设计）
- 包含"配置"（功能动词）

**改写步骤**：
1. 痛点保留："每次都要重教 AI？"（"重讲"改"重教"）
2. 删除功能模式："把...分开配置"全部删除
3. 替换为用户结果："一次配置，永久记住"
4. 或替换为降低门槛："问你 3 个问题就能配好"

**改写后**：
```
每次都要重教 AI？一次配置，永久记住
```

**检查**：不包含任何功能模式 ✓

#### 6.1 用 7 个深度标准检查

对初步胜出标题执行 7 项深度检查（详见"深度判断标准"章节）：

| 标准 | 检查问题 | 不通过的改进方向 |
|------|---------|----------------|
| 1. 功能 vs 结果 | 标题是功能描述还是用户结果？ | 把功能词改为结果词 |
| 2. 抽象 vs 具体 | 有抽象词吗？ | 用数字/动作/场景替换 |
| 3. 书面语 vs 口语化 | 读起来像官方公告吗？ | 改为口语表达 |
| 4. 产品视角 vs 用户视角 | 主语是产品还是用户？ | 改为用户视角 |
| 5. 情绪强度 | 有感染力吗？ | 加入时间词/情绪词 |
| 6. 信息密度 | 包含 2+ 信息点吗？ | 补充对应信息 |
| 7. 删除测试 | 删掉产品名仍有吸引力吗？ | 用痛点/结果替代产品名 |

#### 6.2 执行优化（如果有 2+ 项不通过）

**示例优化过程**：

**初步胜出标题**：
```
每次开新对话都要重讲？先把稳定要求放对位置
```

**7 项检查结果**：
- 标准 1（功能 vs 结果）：❌ "放对位置"是功能
- 标准 2（抽象 vs 具体）：❌ "稳定要求"是抽象词
- 标准 3（书面语 vs 口语化）：⚠️ "重讲"偏书面语
- 其他 4 项：✓ 通过

**判断**：有 2-3 项不通过 → 必须优化

**优化动作**：
1. "放对位置"（功能）→ "永久记住"（结果）
2. "稳定要求"（抽象）→ 删除，让方案本身说话
3. "重讲"（书面语）→ "重教"（口语化）

**优化后标题**：
```
每次都要重教 AI？一次配置，永久记住
```

**再次检查 7 项标准**：
- 全部通过 ✓ → 可以输出

#### 6.3 参考对照表（最后一步）

在输出前，查看"标题改进对照表"（本文件"第二部分之附录"），确认当前标题不在"初稿"列表中。

如果发现类似初稿，参考"改进版"进行最后调整。

### 步骤 7：只输出最终优化版本

**默认行为**：只输出经过二次优化的最终标题，不展示候选、评分、7 项检查或推理过程。

**例外**：用户明确要求"给我看备选"或"为什么选这个标题"时，才展示过程。

**重要**：内部必须执行步骤 6 的二次优化，但不要在交付物中写"二次优化""7 项检查""改进版"等过程说明。用户看到的应该是最终结果。

## 第五部分：常见问题与修正方法

### 问题 1：策略摘要填了，但标题还是很平

**症状**：
- 策略摘要写了"核心价值：根据真实工作选择配置位置"
- 封面标题："配置位置的选择方法"
- 问题：标题没有体现核心价值

**诊断**：
- 翻译规则 1 没有执行
- 只是改写了策略字段，没有转化为用户语言

**修正步骤**：
1. 重读"核心价值"，问："用户真正想要什么？"
   - 不是"选择配置位置"，而是"让 AI 记住习惯"
2. 重读"TA 触发场景"，问："什么时刻让用户意识到问题？"
   - "每次开新对话都要重新解释"
3. 用模式 1 重写：
   - "每次都要重教 AI？一次配置永久生效"

**修正前后对比**：
- ❌ "配置位置的选择方法"（功能描述）
- ✓ "每次都要重教 AI？一次配置永久生效"（痛点+结果）

---

### 问题 2：标题用了模式，但还是像 AI 写的

**症状**：
- 用了模式 1："配置问题？这个方案一劳永逸"
- 问题：虽然有结构，但缺少具体细节，看起来机械

**诊断**：
- 机械套用模板，没有填入具体细节
- 缺少只有这个产品才有的特征

**修正步骤**：
1. 把抽象词替换成材料中的具体词
   - "配置问题" → "每次都要重教 AI"
   - "一劳永逸" → "一次配置永久生效"
2. 增加一个独特细节
   - "这个方案" → 明确是什么方案
3. 用口语化表达
   - "进行配置" → "配一下"

**修正前后对比**：
- ❌ "配置问题？这个方案一劳永逸"（抽象+机械）
- ✓ "每次都要重教 AI？一次配置永久生效"（具体+口语）

---

### 问题 3：阅读路径写了，但页序还是功能目录

**症状**：
- 阅读路径："认出问题 → 相信方案 → 行动"
- 实际页序：配置位置 → 使用入口 → 权限说明 → 安装步骤
- 问题：页序和路径不匹配

**诊断**：
- 翻译规则 5 没有执行
- 把"产品有什么"当成了"读者需要什么"

**修正步骤**：
1. 重读"主要疑虑"
2. 每个疑虑对应一页
3. 按疑虑出现的自然顺序排页
4. 删除不能消除疑虑的功能介绍页

**修正前后对比**：
- ❌ 页序：配置位置 → 两种入口 → 权限边界 → 迁移策略（功能目录）
- ✓ 页序：认出问题 → 核心方案 → 消除"会不会复杂" → 行动（决策路径）

---

### 问题 4：每页都推动决策，但读起来还是像硬广

**症状**：
- 每页都在说产品好
- 语气像在推销
- 用户感觉不自然

**诊断**：
- 内容类型判断错误
- 把教程或方法强行写成产品销售

**修正步骤**：
1. 重新判断内容类型（产品/教程/观点/案例/资源）
2. 调整传播目标和 CTA
3. 降低销售感，增加实用性

**修正前后对比**：
- ❌ 类型：教程 → 目标：购买 → CTA："立刻购买"（错位）
- ✓ 类型：教程 → 目标：收藏应用 → CTA："收藏这份清单，下次遇到直接用"（匹配）

---

### 问题 5：证据匹配了，但 Amplification 还是负面

**症状**：
- PAGE 04 整页讲："不会触发文件修改""不包含个人配置""不复制聊天记录"
- 问题：越看越担心，不想尝试了

**诊断**：
- 过度强调边界和风险
- 防御性表达强化了复杂感

**修正步骤**：
1. 识别哪些内容在强化"不会做什么"
2. 改写成"会做什么"或"如何保护你"
3. 用主动表达替代防御表达

**修正前后对比**：
- ❌ "问一句'能不能配置'，不会触发文件修改"（防御）
- ✓ "先预览，确认后才执行"（主动，体现控制权）
