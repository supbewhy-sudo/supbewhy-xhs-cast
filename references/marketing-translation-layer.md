# 从策略到小红书上屏文案的翻译层

## 作用

本文件只负责把已经确认的传播策略转成页面职责、标题和上屏文字。它不负责补齐缺失的 TA 场景、当前替代、疑虑、数字或效果。

先完成 [营销传播判断方法](marketing-communication-method.md) 的来源账本。只有“已提供”或“已核实”的事实可以转成公开文案；“规划决定”只能控制页序和表达结构；“待确认”不得上屏。

## 翻译顺序

### 1. 把阅读路径翻成页面职责

先为每一页写一句不上屏任务：

`本页让读者从尚未看到/分清/拿到 X，变成已经看到/分清/拿到 X。`

X 必须是材料中的信息，不是推测的心理。例如：

- 可用：`尚未看到安装边界 → 已经知道支持的运行环境与不支持事项`
- 不可用：`尚未放心 → 已经完全信任`

后一种心理变化既无法从材料定位，也不能由一页文案保证。

### 2. 选择封面承载的信息

在后续页面的主张和证据确定后，再反向确定封面主标题。它必须压缩整组卡片最终传达的核心判断、答案或交付，不能只负责吸引点击。问句可以使用，但必须准确覆盖整组的主要内容，并被后续页面充分回答。

封面优先顺序：

1. 材料明确给出的任务或触发时刻
2. 对象的已知输入与可证明交付物
3. 有证据支持的具体结果
4. 对象是什么及最重要差异

内部机制、步骤数量、标题生成方式和营销术语不优先成为封面。只有当用户正在寻找该机制，且材料明确证明它是选择关键时，才可上封面。

几种可用标题形态：

| 页面需要 | 标题形态 | 使用条件 |
|---|---|---|
| 识别任务 | `{明确任务或输入}，接下来怎么处理？` | 任务来自用户或材料 |
| 说明交付 | `从{已知输入}到{可证明交付物}` | 输入输出均可核实 |
| 给出答案 | `{对象}的核心答案是{已知结论}` | 结论有来源 |
| 呈现对比 | `{来源支持的旧做法} vs {新做法}` | 当前替代有来源 |
| 展示证明 | `看一次真实输入如何变成实际输出` | 有真实产物可展示 |
| 明确边界 | `{适用条件}下能做什么，不能做什么` | 边界已核实 |
| 推动行动 | `{准确入口}：完成一个具体动作` | 安装或行动路径已核实 |

这些是选择器，不是必须覆盖的模式库。不要为了使用某种形态而制造数字、问题、反差或情绪。

### 3. 把核心价值翻成读者能理解的交付

核心价值优先写成：

`已知输入 → 对象完成的动作 → 可证明交付物`

例如，功能合同明确支持时：

- 功能表述：`读取材料并输出逐页规划`
- 可用价值：`把一份材料整理成包含上屏文案、页序和制作交接的卡片方案`
- 越界效果：`从此不再返工，传播效果大幅提升`

前两句可以由功能文档支持；最后一句需要真实案例或数据。

### 4. 把差异翻成可见对照

只有材料提供当前替代时才做替代对比。对比必须使用同一任务、同一评价维度：

| 有来源的替代 | 核心差异 | 可见表达 |
|---|---|---|
| 按 README 章节直接拆页 | 按读者需要的信息重新排序 | `不是复述章节，而是重排读者从理解到行动的路径` |
| 用户手工逐页规划 | 输出包含可制作交接 | `从逐页想内容，变成一次拿到整组制作规格` |

如果替代没有来源，改成正面说明产品做法，不自行创造“旧做法”。

### 5. 把疑虑翻成证据任务

疑虑只有两种合法来源：

- 用户或材料明确提出的疑问
- 已核实的成本、风险、限制或失败条件

每个疑虑对应一种证据：

| 需要确认什么 | 合适证据 | 不能替代它的内容 |
|---|---|---|
| 是否具备某项功能 | 文档、界面、可复现演示 | “功能强大”等形容词 |
| 实际输出是什么 | 真实输入与完整输出 | 输出字段目录 |
| 是否带来某种效果 | 前后案例、数据、独立反馈 | 产品 README 或规则自述 |
| 是否安全或适用 | 权限说明、边界、失败条件 | 模糊的“放心使用” |
| 如何开始 | 已核实安装步骤 | 只写仓库名称 |

没有真实效果证据时，页面职责应是“让读者看到功能合同或实际输出”，不是“让读者相信效果”。

### 6. 把 CTA 翻成一个动作

CTA 必须与传播目标一致，并包含准确对象和入口：

- 理解：查看完整说明或示例
- 验证：用提供的材料运行一次
- 安装：执行已核实命令或进入安装页
- 收藏：保存某份可复用清单

一组卡片只保留一个首要 CTA。不要同时要求关注、点赞、评论、私信、安装和转发。

## 标题协调，不是标题统一

标题在页面职责确定后编写。整组检查以下四项：

1. 对象称谓一致：不要在 XHS CAST、标题工具、Claude Skill、内容助手之间无理由切换。
2. 叙述视角协调：不要一页对读者说“你”，下一页突然变成开发文档语气。
3. 语气协调：理性说明、提问、行动可以共存，但不要无来源地突然夸张或恐吓。
4. 信息密度协调：避免一页只有口号，另一页塞满完整说明书。

不检查也不强制：

- 最长与最短标题的固定字数差
- 至少几个标题必须包含数字
- 全部标题使用同一种句式或模式
- 全部页面使用相同情绪强度

不同页面本来就承担不同职责。封面可以是能够概括整组并被后续充分回答的任务提问，证明页可以是事实陈述，末页可以是行动指令。

## 公开页面的信息层级

每一页先确定要传达的一条主信息，再按以下职责写上屏文案：

| 层级 | 职责 | 验收方法 |
|---|---|---|
| 封面主标题 | 概括整组的核心判断、答案或交付 | 读完全组后，标题承诺仍准确且已被兑现 |
| 单页主标题 | 概括本页正文的主要事实、判断或行动标准 | 只看标题就能准确预期本页主要信息 |
| 单页正文 | 解释、展开或证明标题，补足必要事实、原因、做法、证据或边界 | 删掉正文后会丢失理解标题所需的信息 |
| 标签 | 只帮助导航、分组或建立视觉层级 | 删掉所有标签后，标题与正文仍可独立理解 |
| 来源与证据边界 | 限定主张性质和结论上限 | 标题不比正文和来源能够支持的结论更强 |

分类名、步骤名、数字预告、栏目名和短标签不是主信息，不得用它们代替主标题或正文。

## 标题五项测试

每个标题都要通过：

| 测试 | 通过条件 |
|---|---|
| 任务相关 | 相关读者能看出为何要读这一页 |
| 来源可追溯 | 场景、比较、数字、结果和情绪都有来源 |
| 页面有新增 | 标题说的是本页新增信息，不重复上一页 |
| 脱离正文仍清楚 | 知道对象、动作或核心结论 |
| 表达自然 | 不像功能名、内部字段或模板拼接 |

失败时修正页面任务或主张，不要只替换更刺激的词。

## 上屏文案压缩

压缩目标是“最少但充分”，不是字数最少。删除重复、制作说明和低价值过渡；保留让标题成立所需的事实、解释、证据与边界。

按以下顺序保留信息：

1. 让本页成立的核心事实或答案
2. 读者理解它所需的最少解释
3. 与主张一一对应的证据或来源
4. 必要边界或下一步

删除：

- 与本页职责无关的功能
- 重复标题的正文
- 内部字段名，如“战略 TA”“翻译规则”“全局一致性检查”
- 制作说明，如“这里放截图”“重点强调”
- 无证据修饰，如“轻松”“高效”“一劳永逸”“大幅提升”

制作信息保留在不上屏交接区。

## AI 工具或 Skill 的产品介绍示例

假设材料只确认以下事实：

- XHS CAST 接收选题、产品、教程等材料。
- 它输出页序、上屏文案和视觉制作交接。
- 它不直接生成图片，也不自动发布。
- 安装入口针对 Codex，尚无独立效果案例。

合格路径：

1. `从一份材料，到一套能进入制作的小红书卡片规划`
2. `XHS CAST 先安排读者需要的信息，再决定分几页`
3. `一次实际输入会得到这些逐页结果`——展示真实产物
4. `它负责规划，不代替制图和发布`——说明边界
5. `在 Codex 安装 xhs-cast`——提供准确动作

这条路径必须保持“输入与交付 → 产品与差异 → 真实产物 → 能力边界 → 准确行动”。标题质量控制、内部字段或固定输出区块不能替代其中任何一页；环境、许可证和成本必须分别核实。

## 交付前翻译检查

- [ ] 封面承载的是任务、输入、交付或有证据的结果，不是内部机制。
- [ ] 读完全部页面后，封面主标题仍准确概括整组主信息，且后续页已兑现承诺。
- [ ] 页面状态只描述已知信息变化，不虚构心理变化。
- [ ] 替代、疑虑和对比都有来源；没有来源就没有上屏。
- [ ] 每页标题完成不同职责，没有为统一而强制同形。
- [ ] 每页标题准确概括正文主信息，正文直接解释、展开或证明标题。
- [ ] 删除标签、图标和分类名后，页面仍能通过标题与正文独立传达信息。
- [ ] 上屏文字是最少但充分，不是只剩分类词、短句或未回答的问题。
- [ ] 功能合同、实际产物和效果证据被明确区分。
- [ ] CTA、运行环境、许可证和成本表述已经核实。
