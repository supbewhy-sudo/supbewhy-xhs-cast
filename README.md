# supɃewhY-XHS-CAST

**XHS CAST（小红书卡片策略工具）**把选题、产品、教程、观点、案例或资源，整理成可直接制作的小红书多页卡片规划，并同步生成配套笔记。

它不是把原材料机械地拆成几页，而是先回答三个问题：给谁看、为什么值得继续看、读者下一步做什么。随后再把答案组织成阅读路径、标题组、逐页文案和视觉执行规格。

## 它解决什么问题

很多内容有信息，却没有清晰的阅读路径：封面说不清对象，页面顺序像功能目录，标题各写各的，关键主张也找不到证据。

XHS CAST 会在分页前完成传播判断，再组织卡片内容，让一份原始材料变成读者能看懂、设计师能制作的整组页面。

## 适合哪些任务

- 介绍 GitHub 项目、AI 工具、Skill 或产品
- 把教程、方法或观点整理成多页卡片
- 为案例、复盘或资源清单设计阅读路径
- 优化太平、太像功能目录或缺少整体感的卡片标题
- 把文案规划交给 Guizang 或其他制卡工具继续制作

## 核心能力

### 先确定传播方向

从材料中识别目标读者、真实任务、当前替代、核心价值、主要疑虑、证据和唯一行动，避免一开始就进入功能罗列。

### 用阅读路径决定页数

默认规划 3-5 页。每页只承担一个主要任务，页面顺序来自读者从停留、理解、相信到行动的变化，而不是照搬文档目录。

### 统一整组标题

先生成全部页面标题，再一起检查长度、表达风格、量化程度和情绪强度。需要调整时批量改写，避免每一页像由不同的人完成。

### 交付可制作的页面规格

每页包含页面任务、读者变化、上屏文字、重点词、布局意图、画面关系、证据素材和制作备注，可继续交给设计师或制卡工具执行。

### 保持事实边界

不虚构案例、数据、用户反馈或效果承诺。材料不足时保留待补证据位，不把猜测写成事实。

## 快速开始

在 Codex 中可以直接让系统安装：

```text
使用 $skill-installer 从 https://github.com/supbewhy-sudo/supbewhy-xhs-cast 安装 xhs-cast
```

安装完成后，在新任务中调用：

```text
使用 $xhs-cast 规划一个 GitHub 项目的小红书卡片

材料：https://github.com/用户名/项目名
目标读者：第一次接触这类工具的人
希望读者完成的动作：阅读项目并开始尝试
```

也可以提供本地文档、产品 brief、教程草稿或已有文案。信息越完整，页面主张和证据要求越具体。

## 你会得到什么

一次完整规划通常包含：

1. **传播策略摘要**：内容类型、目标读者、真实任务、核心价值、疑虑、证据与行动
2. **方案摘要**：推荐页数、核心答案、阅读路径和页数理由
3. **整组标题**：统一检查长度、风格、量化程度与情绪强度
4. **逐页卡片规划**：每页的上屏文案、信息层级、布局关系、素材和制作要求
5. **配套小红书笔记**：标题、正文、标签和发布建议，与卡片使用同一核心价值

视觉交接使用 `PRIMARY`、`ACCENT`、`FOCAL`、`SUPPORT`、`EVIDENCE` 等语义角色。具体颜色、字体、尺寸和 Recipe 由制卡阶段根据所选风格解析，不把某一次项目的视觉选择写死在 Skill 里。

## 输出示意

```text
输入
一个 GitHub 项目链接 + 目标读者 + 希望读者采取的动作

输出
├── 一句话定位与唯一核心价值
├── 3-5 页阅读路径与页数理由
├── 一组风格统一的页面标题
├── 每页可直接上屏的文字与证据要求
├── 交给设计或 Guizang 的视觉执行规格
└── 一篇与卡片一致的配套小红书笔记
```

页数不是固定模板。只有当解释、步骤或证据无法安全合并，并且每页都有不可替代的任务时，才会增加页数。

## 边界

- 不自动发布小红书
- 不把制图、截图或外部验证描述成已经完成
- 产品自述只能作为产品信息，不能冒充独立效果证据
- 不替制卡阶段决定具体 Style、Theme、Recipe、颜色或字号
- 最终发布前仍需由内容负责人核对链接、事实、版本和授权范围
